# 概率调节引擎（深度拟真）

配置整体存于 `rule_configs.data (JSONB)`，由 `packages/shared/src/schema/ruleConfig.ts` 的 zod 定义校验。
**统一约定**：

- 所有概率 `p` 取值 `0 ~ 1`，UI 用百分比滑块。
- 所有时间单位为**秒**，UI 可切「秒 / 分」。
- 数组型范围 `[min, max]`，`min <= max`。
- `enabled` 是总开关，关闭后该项直接不参与抽签。
- **字卡占比不强制求和为 100%**：引擎先算 `sum`，再按 `p / sum` 归一化；`sum === 0` 回落纯文字。
- 每次抽签结果写入 `messages.plan`，便于在「统计」页复盘真实分布。

## 抽签顺序（权威顺序）

> 这套顺序有**两份实现**，抽签步骤一字不差：
> - `apps/server/src/engine/reply-engine.ts` —— 多端 / 真机（NestJS，接 LLM / MiniMax / 搜索）
> - `apps/web/src/lib/engine/planner.ts` —— 本机（离线可用，见下节「出稿方」）

1. `readNoReply` → 命中则**已读不回**，结束（仍记录 `plan`）。
2. `pat` → 命中则先发拍一拍（后缀从**拍一拍库**里随机抽一条），再继续。拍一拍是「动作」，**不占第 8 步的句数额度**。
3. `weights` 归一化 → 决定载体：文字 / 颜文字 / 表情包 / 图片。
4. `multiCard` → 命中则取 `[min, max]` 张拼接；否则单张。
5. 若 `freeSentence` 或载体为文字 → 走 LLM 组句，注入 `conjunction`、`punctuation`、`pinyinSentence`。
6. `recall` → 命中则延迟 `2~6s` 撤回，再按 `recallResend` 决定补发。
7. `quote` → 命中则带上引用块。
8. `replySentences` 定句数，逐句之间插入 `typingIndicator` 节奏。
9. `voice` → 命中且**已接通**时，把第 4~8 步里**本来就要说的某一句**标记成语音（避开拼音串与超过 `voice.maxCharsPerVoice` 的长句）；合成在 `runtime` 到点时做，失败退回文字。
   - `search` **不在**这条链上：联网搜索推送是**独立的排程**（`lib/engine/search.ts`，见「联网搜索推送」一节），
     回复轨迹里只留一行说明 —— 免得「你没说话他却在推卡片」看起来像是回你的。
   - **前置**：如果第 4~5 步抽中的字卡**自带语音**（`cards.voice`，见「语音卡」），且这一轮说的就是那张卡的原话（`bareSentence` 忽略标点比对），
     就直接用这段现成音频 —— 这一轮**不掷 `voice.p`、也不合成**（`voice.enabled` 关着也一样能发），轨迹里多一步「语音卡」。
10. `pickup` → 反向抽签，把我上一句存入**他的**字卡库。

### 主动消息：他也会自己来找你（`proactive.message`）

回你的那套顺序不变，**主动**只是换了触发源 —— 同一个 `planner`，但：

| 步骤 | 主动模式下 |
| --- | --- |
| 1 已读不回 | 换成 **主动触发**（他自己决定来一句，不是回你） |
| 7 引用回复 | 跳过（没有「你的上一句」可引用） |
| 8 句数 + 延迟 | 不变（主动也可能连发 1~3 句） |
| 10 拾取 | 跳过（同上） |
| 「正在输入」 | 不显示（自发消息不该有预告） |
| 气泡标识 | `messages.proactive = true` → 左上角 ❤️（一次主动只标第一条） |

什么时候触发，由四个旋钮决定（都在 `proactive.message` 里）：

| 旋钮 | 语义 | 本机实现 |
| --- | --- | --- |
| `interval [min,max]` | 距**最后一次说话**多久后来找你（秒，随机落在区间内） | 每次有新消息（我的 / 他的）就重排定时器 = 从最后一次活动重新计时；你们在聊，他就不会插嘴 |
| `dailyLimit [min,max]` | 每天主动几条 | **按日期稳定地抽一个额度**（今天说得多、明天说得少）；从聊天记录里数今天已发的主动条数，用完顺延到明天 |
| `cancelIfRepliedWithin` | 被打断窗口（秒） | 要发的那一刻你若在窗口内说过话 → 这条取消，重新计时 |
| `quietHours [起,止]` | 免打扰时段（支持跨零点，如 23:00~07:00） | 排程时落在里面就顺延到时段结束 + 抖 0~15 分钟；fire 时再兜一次底 |

> 不穿帮的两个细节：① 时间基准是「最后一条消息」而不是「打开 App 的时刻」，所以刷新 / 关机再开不会重新数一遍；② 排到的时间已经过去（关机很久）时，会等 30 秒再冒出来，不会一开 App 就弹。
> 想立刻看效果：**设置 → 概率调节引擎 →「现在就来一条」**（手动预览，跳过上面四道闸，轨迹里会写明「手动预览」）；或者把 `主动间隔` 调到 60~120 秒等它自己来。
> 主动消息的轨迹里 `trigger: 'proactive'`、第 1 步是「主动触发」，长按 →「看抽签」能看到它和回复走的是同一套抽签。

### 朋友圈 / 信箱：他刷到你的动态、读到你的信

这两块不走「抽签出稿」，而是**时间轴**（`lib/engine/timeline.ts`）：所有待办都从数据推导，不存定时任务表。

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他主动发朋友圈 | 冷却过了 + 这个节拍掷中 + 不在免打扰 | `proactive.moment.enabled` / `.p` / `.cooldownMin` |
| 他主动写信 | 同上 | `proactive.letter.enabled` / `.p` / `.cooldownMin` |
| 他给我发的动态点赞 | 我发动态那一刻 + 随机延迟 | `moment.like.p` / `moment.like.delay` |
| 他评论我的动态 | 同上 | `moment.comment.p` / `moment.comment.delay` |
| 他回复我的评论 | 我评论那一刻掷一次 | `moment.replyMyReply.p` |
| 我给他点赞后他回赞 | 同上 | `moment.likeBackIfILiked.p` |
| 他回我的信 | 我寄出那一刻 + 回信延迟 | `mail.reply.enabled` / `.p` / `mail.replyDelayH` |
| 他读我的信时写蓝笔批注 | 与回信同一时间基准，但**各自掷签**（所以会「只批注不回信」） | `mail.annotation.enabled` / `.p` |

三个不穿帮的细节：

1. **掷签用种子随机**（`seed.ts`，种子 = 那条动态 / 那封信 / 那条评论的 id）：刷新一次不会多掷一次，
   同一件事的结果永远一致 —— 否则每刷一次页就等于把概率悄悄放大一次。
2. **`proactive.moment` / `proactive.letter` 只有「概率 + 冷却」，没有间隔**，所以给它们一个 **20 分钟节拍**：
   每个节拍掷一次签，冷却没到直接跳过，**同一个节拍只发一条**（不然冷却设成 0 会无限发下去）。
3. **时间基准是那条记录自己的时间**（不是「打开 App 的时刻」）：信是昨晚寄出的、回信延迟 6 小时，那今天开机就能看到回信；
   已经到点的事件会等 20~90 秒再发生，不会一开 App 全弹出来。

### 递东西：抉择 / 问卷 / 红包 / 礼物 / 音乐 / 涂鸦 / 通话

也是时间轴，但**种子 = 那条消息的 id**（一张卡只掷一次签）：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他做你的抉择 | 卡片时间 + 回答延迟（`p` 落空就一直停在「等他选…」） | `choice.enabled` / `.p` / `.delay` / `.reason` / `.maxReasonChars` |
| 他填你的问卷 | 卡片时间 + 交卷延迟；每题按 `skipPerItem.p` 决定留空 | `question.enabled` / `.p` / `.delay` / `.skipPerItem.p` / `.noteP` |
| 他主动来问你 | 每天按 `askMeP` 从题库挑一套，冷却内不重复问；到点在聊天里发来（种子 = 日期） | `question.enabled` + `question.askMeP` + `question.askCooldownMin` |
| 默契问卷 | 两个人做同一套；`seriousP` 决定他认真选还是随机选，交卷后按一致率算默契度 | `question.enabled` + `question.seriousP` |
| 他领你的红包 | 卡片时间 + 领取延迟（不领就一直躺在聊天里） | `redPacket.claim.enabled` / `.p` / `.delay` |
| 他说声谢谢 | 和「领不领」是**两件独立掷签的事** | `redPacket.thanks.enabled` / `.p` |
| 他回你一个红包 | 和上面两件**再独立掷一次**（已经回过就不再排） | `redPacket.back.enabled` / `.p` / `.amount` / `.delay` |
| 他收下你的礼物 | 卡片时间 + 收下延迟 | `gift.accept.enabled` / `.p` / `.delay` + `gift.thanks` |
| 他主动送你礼物 | 冷却过了 + 20 分钟节拍掷中（和朋友圈同一套节拍逻辑） | `gift.giveMe.enabled` / `.p` / `.cooldownMin` |

| 他聊一句这首歌 | 加入之后独立掷一次 | `music.say.enabled` / `.p` |
| 他回推一首歌 | 加入之后独立掷一次（每次邀请最多一首） | `music.shareBack.enabled` / `.p` |
| 他看你的涂鸦并回话 | 画的时间 + 回话延迟 | `doodle.reply.enabled` / `.p` / `.delay` |
| 他画一张回你 | 回话之后独立掷一次 | `doodle.drawBack.enabled` / `.p` |
| 他主动画给你 | 不等你先画；冷却过了 + 20 分钟节拍掷中 | `doodle.proactive.enabled` / `.p` / `.cooldownMin` |
| 他收藏我的东西 | 每条内容独立掷一次（种子 = 内容 id），冷却内不重复收 | `favorite.collect.enabled` / `.p` + `favorite.cooldownMin` |
| 通话接通 | 拨出后**先掷一次**「接不接」（`connect.p`），没接再按 `busy` / `miss` / `reject` 的权重给个理由 | `call.connect.p` / `call.busy.p` / `call.miss.p` / `call.reject.p` |
| 响铃时长 / 通话时长 | 接通延迟 `call.connect.delay`；通话时长在 `[45s, maxDurationMin]` 里抽，`call.hangup.p` 决定他会不会中途先挂 | `call.connect.delay` / `call.ringTimeoutSec` / `call.hangup.p` / `call.maxDurationMin` |
| 挂断后他补一句 | 挂断 + 几秒，独立掷一次（接通与否都会用不同的语气） | `call.afterTalk.enabled` / `.p` |

> 这些卡片**不再触发聊天回复引擎**（`cards.ts` 的 `CARD_KINDS` + `isQuietKind()`），
> 否则一张卡会同时触发「他随口回一句」和「他认真答这张卡」两套排程。

#### 一起听房间里（`lib/engine/room.ts`）

房间的「一次会话」＝ 停下来超过 10 分钟之后再播。种子 = **曲目 id + 10 分钟节拍**，
所以同一节拍内刷新页面不会重新掷签（不会因为刷新就把概率悄悄放大）：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他进房间 | 会话开始 + 他还没在房间里（不在就每秒回来看一次，等他进来才排后面的事） | `music.join.enabled` / `.p` / `.delay`（上限 30 秒） |
| 他待多久 | 进房间时抽一次；到点他说一句「先去忙了」，这次会话不再进来 | `music.listenMin` |
| 他聊一句这一首 | 歌放到 20%~40%（不到 20 秒的短音频退回到 15~40 秒）；一次会话里每首歌最多一句 | `music.say.enabled` / `.p` |
| 他往歌单加一首 | 歌放到 50%~80%（短音频退回到 45~120 秒）；一次会话里每首歌最多一次 | `music.shareBack.enabled` / `.p` |
| 一起听了多久 | **`<audio>` 真的在走才累加**，每 10 秒落一次盘；网易云也能计数，只有歌名、没有音频地址的曲目不计数 | —（这条没有规则，是真的） |

> 想立刻看效果：**设置 → 概率调节引擎** 顶部的「🌈 让他发条朋友圈」「✉️ 让他写封信」（手动预览，不等概率与冷却）。
> 想看成串的互动：把 `朋友圈冷却` 调 0、`主动发朋友圈` 调到 100%，把 `点赞响应 / 评论响应` 调到几秒，`回信延迟` 调到 0~0 小时。
>
> **写信的三种结果**（`mail.reply.p` 与 `mail.annotation.p` 各自独立掷签）：
> ① 只回信不批注 ② **只批注不回信**——信箱里不会多出新信，但我寄出的那封状态会变成「他读了 · 写了批注」，
> 打开就能看到蓝字落在某一行底下 ③ 又回信又批注。所以「他有没有认真读我的信」和「他有没有回信」是两个独立的问题。

### 陪伴：时长是真的，他做的事也是抽出来的（`lib/engine/companion.ts`）

陪伴（**功能 → 🌙 陪伴**）里的时长**不是动画**：`state.companion.active.startedAt` → 收尾那一刻的真实秒数，
挂在别的页面、切后台、关掉页面再回来都照算（到点自动收尾的**按目标时长封顶**，提前点结束按实际时间记）。

种子 = **这一次陪伴的 id**，所以刷新 / 关机重进都不会重掷；排程同样**从数据推导**（不存定时任务表）：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他到场 | 开始时抽一次：命中 → 1~6 秒内到场；没命中 → 他先说一句「N 分钟后过去陪你」，到场时刻存在 `heComingAt`，每秒 tick 到点才真的进来 | `companion.join`（命中）+ `companion.joinDelay`（没命中时「一会儿」有多久） |
| 他中途说一句 | **每 10 分钟一个节拍**掷一次签（第 0 个节拍不说，开场已经说过）；命中就说一句带「还有 N 分钟」的话；不定时的那种不带剩余时间 | `companion.say` |
| 他先走 | 开始时抽一次「会不会先走」+「几点走」，存在 `heLeavesAt`；到点他留一句「我先走一步」→ 之后**陪伴继续计时，他不再出声**（房间里也不回你） | `companion.leave` + `companion.leaveAfterMin` |
| 我在房间里说话他接不接 | 每说一句掷一次（种子 = 陪伴 id + 房间消息数），命中则 1~4 秒后回一句 | `companion.replyMe` |
| 收尾 | 到点（`plannedMin` 分钟）自动收尾；或我点「结束」（提前结束会标 `interrupted`） | —（时长这条没有规则，是真的） |

> 结束时会在主聊天里落一条**居中的系统小字**（`kind: SYSTEM`，如「📚 和黎深一起学 · 45 分钟」）——
> `SYSTEM` 属于 `isQuietKind()`，**不会再触发聊天回复引擎**（不会因为这条又回你一句）。
> 记录（`state.companion.sessions`）里会标「提前结束 / 他先走了 / 他没来」，「今天 / 连续 / 一共」三个数字都是**现算**的。

### 观影室：进度是真的，他的弹幕才是抽出来的（`lib/engine/watch.ts`）

观影室（**功能 → 🎬 观影室**）先把两件事分清楚，这是这个模块的**红线**：

| 东西 | 是不是真的 | 怎么算的 |
| --- | --- | --- |
| 看到第几秒 / 一共看了多久 | ✅ 真的 | 本机视频文件与直链都走我们自己控的 `<video>`（`lib/videoEl.ts` 单例）：`timeupdate` 给位置，只有 `<video>` 真在走才按秒累加（每秒结算、每 10 秒落盘），片长由 `loadedmetadata` 测出来写回 `item.durationMs` |
| 我的进度条 / seek | ✅ 真的 | 直接改 `currentTime`，没有「假慢慢走」的模拟条 |
| B 站 / 只有片名的片 | ⚠️ 拿不到进度 | B 站用**官方 iframe 播放器**（`player.bilibili.com`，跨域读不到 `currentTime`）；只有片名的根本没有画面 → 这两种**一秒都不计、一条弹幕都不发**（不在假进度上飘字） |
| 他进不进来 / 发几条弹幕 / 第几秒发 / 说什么 / 会不会先走 | ❌ 抽签 | 全在 `watchRoom.*`，种子 = **这一次观影的 id** |

排程同样**从数据推导**（不存定时任务表），1 秒一趟的钟只做四件事：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他进房间 | 开始时抽一次：命中 → 1~6 秒内到；没命中 → 他先说一句「我这边还有点事，N 分钟后过来」，到场时刻存在 `heComingAt`，到点才真的进来 | `watchRoom.join`（命中）+ `watchRoom.joinDelay`（没命中时「一会儿」有多久） |
| 他发弹幕 | **他到场那一刻一次排完**（不是每秒抽）：条数抽一次，每条的位置 = 片长的 5%~95% 里种子散开，**当场落库**；界面只在播放进度越过 `atSec` 时才让它飘出来 → 刷新重进还是同一批、同一时刻，同一个时间点不会「又抽一次」 | `watchRoom.danmaku` + `watchRoom.danmakuCount` |
| 房间里说一句 | 拿得到进度时按**片子进度**抽（片长的 35%~75%，一次观影最多一句）；拿不到进度（B 站 / 只有片名）就按**真实待了多久**（3~10 分钟） | `watchRoom.say` |
| 他先走 | 开始时抽一次「会不会先走」+「几点走」，存在 `heLeavesAt`；到点他留一句 → 之后**片照放，他不发声**（房间里也不回你） | `watchRoom.leave` + `watchRoom.leaveAfterMin` |
| 我在房间里说话他接不接 | 每说一句掷一次（种子 = 观影 id + 房间消息数），命中则 1.2~4.4 秒后回一句 | `watchRoom.replyMe` |
| 收尾 | 我点「看完了 / 先停在这儿」；「这一场真的看了多久」= 收尾时的累计播放秒数 − 开始时的累计（**不是墙上时间**） | —（时长这条没有规则，是真的） |

> **片长是弹幕的前提**：片长拿不到（`Infinity` / `NaN` / 0）就一条都不排（直播流、边录边播的 webm 都算「不知道」）；
> 片长不到 15 秒的也不飘（一次要飘 8 秒，比片子还长就成了干扰）。一整场里不重复同一句弹幕。
> 结束时聊天里那条 `SYSTEM` 有真实进度才带时长（「🎞️ 和黎深一起看了《…》 · 42 分钟」），
> B 站 / 只有片名的就只写片名 —— 宁可少一个数字，也不编一个。

### 阅读室：读到第几段是真的，他写的那几处才是抽出来的（`lib/engine/read.ts`）

阅读室（**功能 → 📖 阅读室**）跟观影室同一套分工，但「进度」在读书这件事上更含糊，所以口径先说死：

| 这件事 | 真的假的 | 怎么来的 |
| --- | --- | --- |
| 「读到第几段」/ 百分比 | ✅ 真的 | 正文（本机 txt / md / html / epub 或粘进来的）解析成**段落数组**存本机 IndexedDB（`book:<id>`，不进 `state`）；阅读器按段分页，段号由我们自己数，百分比 = 段号 / 总段数 |
| 「一起读了多久」 | ✅ 真的，但**不是墙上时间** | 三条同时成立才走表：阅读室开着 + 页面在前台（`document.visibilityState === 'visible'`）+ **最近 45 秒内翻过页 / 滚过 / 点过**；每秒结算、每 10 秒落盘。倒杯水回来接着读不算断，挂机刷手机 / 页面丢后台就不走表 |
| 只有书名的书 | ⚠️ 没有进度 | 没有正文 → **没有「读到第几页」**，**一秒都不记时长**，**页边一处都不写**（不在假进度上写字）；就是他陪着你待一会儿，房间里照样说话 |
| 他在第几段写批注 / 写什么 / 什么时候说一句 / 会不会先走 | ❌ 抽签 | 全在 `readRoom.*`，种子 = **这一次共读的 id** |

排程同样**从数据推导**（不存定时任务表），1 秒一趟的钟只做四件事：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他进房间 | 开始时抽一次：命中 → 1~6 秒内到；没命中 → 他先说一句「N 分钟后过来」，到场时刻存在 `heComingAt`，到点才真的进来 | `readRoom.join`（命中）+ `readRoom.joinDelay`（没命中时「一会儿」有多久） |
| 他写页边批注 | **他到场那一刻一次排完**（不是读到才抽）：处数抽一次，每处的段落号 = 总段数的 5%~95% 里种子散开，**当场落库**；界面只在**你真的读到那一段**时才让它出现在页边 → 刷新重进还是同一批、同一段 | `readRoom.mark` + `readRoom.markCount` |
| 房间里说一句 | 有正文时按**读到的进率**抽（总段数的 35%~75%，一次共读最多一句）；只有书名时按**真实待了多久**（3~10 分钟） | `readRoom.say` |
| 他先走 | 开始时抽一次「会不会先走」+「几点走」，存在 `heLeavesAt`；到点他留一句 → 之后**书照读，他不发声**（房间里也不回你） | `readRoom.leave` + `readRoom.leaveAfterMin` |
| 我在房间里说话他接不接 | 每说一句掷一次（种子 = 共读 id + 房间消息数），命中则 1.2~4.4 秒后回一句 | `readRoom.replyMe` |
| 收尾 | 我点「读完了 / 先停在这儿」；「这一场真的读了多久」= 收尾时的累计阅读秒数 − 开始时的累计（**不是墙上时间**） | —（时长这条没有规则，是真的） |

> **短文本不排批注**：总段数少于 4 段（段落太密、锚不住）就一处都不写，只记一条轨迹。
> 一整本里不重复同一句。结束时聊天里那条 `SYSTEM` 有真实进度才带时长（「📖 和黎深一起读了《…》 · 1 分钟」），
> 「只有书名」的就只写书名 —— 宁可少一个数字，也不编一个。

### 日记：我的不限条数，他自动那条每天最多一次，提的每件事都真的发生过（`lib/engine/diary.ts`）

日记（**功能 → 📔 日记**）没有「房间」，只有一条按天分组的时间线。口径和上面几节一样：**能测的用真的，测不到的才抽签**。

| 这件事 | 真的假的 | 怎么来的 |
| --- | --- | --- |
| 我的日记条数 | ✅ 真的 | 同一天可以写很多条，不写也可以；每条按自己的 `id` 独立改 / 删，改过记 `editedAt` |
| 他自动写的那条 | ✅ 真的（最多一条） | 他今天已经自动写过，就不再自动写第二条；这是他的排程，不是对我的限制 |
| 我写的每一条 | ✅ 真的 | 我自己写的（心情 + 正文），每条都能单独选公开 / 私密，随时能改 |
| 他写不写 / 几点写 / 提不提今天真事 / 写几句 / 会不会顺着我写 | ❌ 抽签 | 全在 `diary.*`，**种子 = 日期**（`YYYY-MM-DD`）→ 今天写不写早上看和晚上看是同一个答案，刷新不重掷 |
| 他留言里提到的每一件事 | ✅ **真的，且只提真的** | `lib/diary.ts#collectFacts()` 从**今天的记录**里一条条数（见下表）；一条都没有就一条都不提，**不编** |

「今天真发生过什么」到底数了哪些（全部按**本地时区的归属日期**过滤）：

| 事实 | 从哪来 | 口径 |
| --- | --- | --- |
| 聊了多少条（我几条 / 他几条） | `messages` | **安静类不算**（`SYSTEM` `CALL_EVENT` `SEARCH_PUSH`），**「东西」也不算**（红包 / 卡片 / 礼物 / 音乐邀请 / 语音各归各自那一条） |
| 语音 | `messages(kind=VOICE)` | 分清我发的 / 他发的 / 来回 |
| 通话 | `messages(kind=CALL_EVENT)` | 只认真的**接通了**的（`phase=ENDED` 且不是 `MISSED`），时长取 `payload.durationSec` |
| 红包 | `messages(kind=RED_PACKET)` | 分**我给他的** / **他给我的**（谁发的看 `senderId`） |
| 礼物 / 一起听 | `messages`（`GIFT` / `MUSIC_INVITE`，独立 kind 或字卡上的 `cardType` 两处都认） | 只有发生了才会出现 |
| 一起看片 / 一起读 | 收尾那条 `SYSTEM` 的 `payload.watch` / `payload.read` | 标题 + **真实时长**（`playedSec` / `readSec`）；「只有片名 / 只有书名」那种没有时长就不带数字 |
| 陪伴多久 | `state.companion.sessions` | 按 `startedAt` 归属到那天；**同一模式同一天只报最长的一次**（不把分段的加总吹大） |
| 他在我朋友圈点赞 / 评论 | `state.moments` | 只数**他做的**（他发的动态、他给我点的赞、他在我动态下的评论），不替他数我自己的 |
| 他寄来的信 | `state.letters` | `fromId ≠ 我` 且归属今天 |

排程**不存定时任务表**（和陪伴 / 观影室 / 阅读室一致），一分钟一趟的钟只问一件事 ——「他到点了吗」：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 他到点写今天那条 | 他今天的「打算写的时刻」= 用日期当种子从 `diary.atTime` 里抽一个点（默认 21:00~23:30，**每次开 App 现算、结果永远一样，所以不用存**）；过点了 → 再看「今天写不写」的抽签，命中就写 | `diary.write`（写不写）+ `diary.atTime`（几点） |
| 顺着我的留言写一条 | 我今天先写了 → 他隔 8~45 分钟（种子 = 日期）后也写一条，开头是「看到你写的了」，中间接一句我的话 | `diary.replyMine` |
| 还没到点 / 今天不写 | 界面上**照实说**：「他今天还没写，一般在你睡前那段（21:00~23:30 之间）」/「今天他不打算写（抽签结果，刷新也不会变）」—— 不是「在加载」 | — |
| 界面上那个「现在就写」按钮 | 只有抽签结果为「今天会写」时才给，点了等于**把他今晚那条提前**（不会凭空多一条） | `diary.write` |

> **他自动那条每天最多一次**：他写过了就不会自动再写第二条。
> 我的日记没有这个限制 —— 同一天随时可以再写一条，每条各掷各的 30% 私密破解。

### 世界感知：他那边的几点是真的，天气一个都不编（`lib/engine/world.ts`）

世界感知（**功能 → 🌍 世界感知**）没有「房间」，只有一条采样台账。三类东西分开标：**能算的算、测不到的抽、没有的不显示**。

| 这件事 | 真的假的 | 怎么来的 |
| --- | --- | --- |
| 他那边的钟点 / 时段 | ✅ **真的** | `我这边现在 + 时差` 真换算（时差是我在界面上设的**设定**，不是测出来的）；时段按他那边的小时数分 |
| 他的状态（在忙 / 刚起床…）与「正在做的事」 | ❌ 抽签 | `world.status` / `world.doing`，**种子 = 日期 + 采样槽** → 同一段时间里反复看是**同一个答案**，刷新不重掷，跨槽才变 |
| 天气 | ⚠️ **没有** | 这台设备没接天气源 → `weather` 恒为 `null`，界面写「没接源，不显示」，**一个字都不编** |
| 「顺手在聊天里说一句」 | ❌ 抽签（每天最多一条） | `world.toChat`；判据是**聊天记录本身**（消息带 `payload.world`），不是采样里的标记 |

状态不是乱抽的：**按他那边的时段分池**（那边半夜抽不到「在开会」，早上也不会「准备睡了」），跨日会标「（他那边是明天）」。

排程同样**从数据推导**（不存定时任务表），60 秒一趟的钟只做一件事 ——「到没到下一个槽」：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 采一条 | 距上一条 >= 当天的采样间隔（间隔 = 用日期当种子从 `world.intervalMin` 抽出来的那个数，**同时就是槽长**）**且** 这一槽的 `sample` 命中 | `world.sample` + `world.intervalMin` |
| 在聊天里说一句 | 采到新的那一条时，今天还没说过、且不在免打扰时段 | `world.toChat` |
| 手动采一条 | 界面上点「现在采一条」（人说了算，不掷签） | — |

> **采样会被裁**（最多 40 条）、**也能手动删**，所以「今天说过没有」这件事必须以**聊天记录**为真 ——
> 否则删掉采样，他会把同一句再说一遍。

### 查岗：报告一半是真的，一半明说是抽的（`lib/engine/check.ts`）

查岗（**功能 → 🔍 查岗**）的红线最硬：**我们拿不到他的定位，也看不到他的手机**。所以报告不糊成一团，**两栏摆**。

| 这件事 | 真的假的 | 怎么来的 |
| --- | --- | --- |
| 他那边现在几点 / 最后一条消息多久前 / 今天发来几条 / 最近一次陪你做了什么 / 今天写没写日记 / 从你这儿拾走过几句话 / 字卡库多少张 | ✅ **真的** | 全部从本机记录现算（`messages` / `state.diary` / `cards` / `state.world`），数字都对得上 |
| 定位 / 手机屏幕上看到的东西 | ❌ 抽签 | 只有候选池（`lib/check.ts` 的 `LOCATION_POOL` / `PHONE_POOL`），**种子 = 请求 id**；界面上标明「抽的」 |
| 他给的是不是「修饰过」的版本 | ❌ 抽签 | `checkPhone.fakeInfoP`，命中则附一句他露的马脚（界面写明这是他**自己承认**改过） |
| 真的截图与坐标 | ⚠️ **永远不给** | 这台设备上没有这种来源 → 宁可不给，也不给你一张假截图 |
| 冷却 | ✅ **真的** | 从我上一次发起的时刻现算 `checkPhone.cooldownMin`，剩多久显示多久；清掉记录就跟着松掉 |

排程（1 秒一趟）：

| 事件 | 什么时候发生 | 相关规则 |
| --- | --- | --- |
| 我发起 → 他回应 | 发起时掷「几秒后回」（3~12 秒），把 `respondAt` **存进记录**；钟到点才结算（同意 / 拒绝，**种子 = 请求 id**）→ 他说一句 + 聊天里落一条安静的系统小字 | `checkPhone.enabled` + `checkPhone.acceptP`（同意率）+ `checkPhone.fakeInfoP` |
| 他来查我 | **种子 = 日期**决定每个名额来不来（`askMeP`）；名额数 = `checkPhone.dailyLimit`（**1~5，默认 1，上限 5**，不是固定一天一条）；到点在界面上挂卡（功能页图标带红点） | `checkPhone.enabled` + `checkPhone.askMeP` + `checkPhone.dailyLimit` |
| 我回应他 | 我点「给他看 / 不给看」→ 落记录 + 他在聊天里回一句 | — |
| `EXPIRED` | **本机版不产生**：他 3~12 秒就回，不存在没人看见的超时（多端版才有） | — |

> 报告的长度是**跟着记录长的**：刚装上、什么都没发生过的时候，「真的」那栏自然很短 —— 数字少就少写，不凑。

### 联网搜索推送：搜到的才是真的，搜不到就一条都不推（`lib/engine/search.ts`）

这个模块最容易造假 —— 编一条「他上网看到……」谁也查不出来。所以规矩先立在最前面：

| 情况 | 做什么 | 不做什么 |
| --- | --- | --- |
| **搜到了** | 推一张 `SEARCH_PUSH` 卡：标题 / 链接 / 站点 / 摘要 / 图**都是搜索服务与上游页面真返回的**；同时记一条**成功**轨迹（写清这次是链接卡 / 图片卡 / 视频卡） | 不替他「点评」那条内容（附言只说「刚刷到·给你看看」这种姿态，不评价也不说自己看过了） |
| **搜不到**（没配 Key / 断网 / 被限流 / 一条结果都没有 / 上游格式看不懂） | 只在「搜索轨迹」里记一条**失败**（人话原因 + 上游原话），界面上能看见「上次为什么没搜到」 | **一条消息都不发**；连「他试着搜了一下但没搜到」这种话都不发 |
| **有图但没验过** | 当没有图：退回纯链接卡，轨迹里写清为什么（「太小」「像图标」「防盗链 403」） | **不放占位图**，也不合成一张「他拍的图」 |

**卡片的形态**（内容说了算，不是随机贴标签）：

| 形态 | 什么时候是它 | 相关规则 |
| --- | --- | --- |
| **视频卡** | 首位结果本身就是**视频页**（域名是视频站 / 页面自带 `og:video` —— 只有这两路硬信号，**实测博查几乎不给视频站结果，所以这种卡很少见**） | —（是事实判断，不掷签） |
| **图片卡** | 服务端**验过**有可用图，且这一槽掷中 | `search.imageP` |
| **链接卡** | 其余情况：真 favicon + 标题 / 摘要 / 链接；有图就带封面 | — |

| 附言 | 推卡时按种子掷一次，中了就配一句「刚刷到这个，给你看看。」 | `search.captionP` |

排程（60 秒一趟，**不存任务表**，全从数据推导）：

| 环节 | 怎么定的 | 相关规则 |
| --- | --- | --- |
| 试不试 | 上一次「试过」的时刻（**轨迹与聊天记录里更晚的那个**）到现在不足一个间隔就跳过；够了再按**种子 = 日期 + 间隔槽**掷一次 | `search.pushIntervalMin` + `search.p` |
| 搜什么 | 同一槽里种子抽一个主题（同一槽刷新不重掷、跨槽才变） | `search.topics` |
| 免打扰 | 正处在 `proactive.message.quietHours` 就这一槽不推 | `proactive.message.quietHours` |
| 真的去搜 | 走**我们自己的后端**（`POST /api/v1/search`）→ 后端调博查 `POST https://api.bochaai.com/v1/web-search` | Key 在「设置 → 接入」填（或 `.env` 的 `SEARCH_API_KEY`），接口只回尾号 |
| 手动推一条 | 「设置 → 接入」里那个按钮：不走排程、不看免打扰，但**同样**是「搜到才推、搜不到只记一条」 | — |

> 为什么走后端：浏览器直连博查会被 CORS 挡，而且 Key 不该下发到前端（和 MiniMax 语音一个路子）。
> 安静类消息：`SEARCH_PUSH` 与 `SYSTEM` / `CALL_EVENT` 一样，**不触发**回复引擎，也不算进「今天聊了几句」。

### 语音：从来不等到发不出去才想起（`lib/voice.ts` + `runtime.ts`）



| 环节 | 行为 |
| --- | --- |
| 出稿时 | `planner` 只**标记**「这条要变成语音」（`PlannedItem.voice`），不碰 `kind` |
| 排程时 | `runtime.startVoices()` 在「正在输入」的这几秒里**提前并行合成**（合成通常 1~3 秒，正好藏在拟真延迟里） |
| 到点时 | 音频好了 → 发 `VOICE` 气泡（`payload.url` + `audioDurationMs` + `via: 'MiniMax'`）；还没好就等一下；**一直没成功 → 退回普通文字**，并把「合成失败，这条退回文字」写进轨迹 |
| 挑句子 | 只挑 `kind: TEXT`、≤ `voice.maxCharsPerVoice`、**不是拼音串**的那一条；没有合适的就写进 `trace.skipped` 跳过（不会把一段拼音念出来） |
| 语音卡（收藏来的现成音频） | 抽中的字卡自带语音（`cards.voice`）→ 这一轮**直接发这段 dataURL**（`payload.via = '语音卡'`、`PlannedItem.voice.url`），**不调 MiniMax、不花钱、也不看 `voice.enabled`**；比对用的是「这一轮的原话」（`bareSentence` 忽略标点），对不上就当普通文字卡发 |
| 缓存 | 键 = 文本 + 音色 + 模型 + 语速 + 情绪；命中直接复用，不重复计费 |
| 打断 | 你在他「正在输入」时又发了一条 → 旧排程整体作废（含**已经拿到音频、正在 await** 的那条，`planSeq` 保证不会被它抢发） |

> 想白嫖这条链路：**长按他发的语音 → ⭐ 收藏**，再进 **功能 → 收藏 ⭐** 点「🎙 变成语音字卡」——
> 字卡库里那张卡会多一个 🎙 角标，之后引擎抽到它就**直接发这段音频**（`trace` 里「语音卡」命中、`via` 写 `语音卡`）。
> 这段音频已经存在消息 / `state.voices` 里了，所以**重听不花钱**；「语音卡」这条路也和 `voice.enabled` 总开关无关。

## 出稿方（谁在跑这套抽签）

本机运行的出稿方是 **web 端本地引擎**，因为它和字卡库 / 规则 / 聊天记录在同一个「本地优先」世界里，**断网也能出稿**：

| 文件 | 职责 |
| --- | --- |
| `apps/web/src/lib/engine/planner.ts` | 纯函数：`planReply({rules, cards, myMessage, mode})` → 要发哪几条（`kind` / 文本 / 延迟 / 撤回 / 引用 / 用哪张卡）+ 抽签轨迹 |
| `apps/web/src/lib/engine/compose.ts` | 「自由组句」的本地兜底：以抽中的字卡为素材拼句（连词 / 标点 / 拼音），并按我上一句的语气挑模板 |
| `apps/web/src/lib/engine/runtime.ts` | 排程：按 `replyInterval` 定时上屏（提前 0.9s 显示「正在输入」）、执行 `recall` 撤回、落 IndexedDB + 推后端；我连发消息时取消旧排程、只回最新那句；**主动消息的定时器**（`scheduleProactive` / `fireProactive`）也在这里 |
| `apps/web/src/lib/engine/proactive.ts` | 主动消息的**纯计算**：间隔抽签 / 每日额度 / 免打扰时段 / 被打断窗口 |
| `apps/web/src/lib/engine/timeline.ts` | 朋友圈 / 信箱的**排程**：发动态、点赞评论、写信回信、蓝色批注（从数据推导，不存任务表） |
| `apps/web/src/lib/engine/content.ts` | 朋友圈 / 信件的**内容生成**（无 LLM 时用模板 + 他的字卡库拼，不假装 AI） |
| `apps/web/src/lib/engine/seed.ts` | 带种子的伪随机：让「他的行为」可复现（刷新不重掷） |
| `apps/web/src/lib/engine/room.ts` · `companion.ts` | 一起听房间 / 陪伴的**排程**（他进房间、聊一句、加歌、先走；他到场、中途说话、先走、收尾）——时间一律是真的 |
| `apps/web/src/lib/engine/watch.ts` · `lib/videoEl.ts` · `lib/watch.ts` | 观影室的**排程 / 播放器 / 片源解析**：他进不进来、排这一场弹幕（位置按片长种子散开、当场落库）、按进度说一句、先走、房间回话；`<video>` 单例给真进度，B 站走官方 iframe（拿不到进度就一秒不计、一条不飘） |
| `apps/web/src/lib/engine/read.ts` · `lib/read.ts` | 阅读室的**排程 / 书源解析**：真读秒（开着 + 前台 + 45 秒内翻过页才走表）、到场那一刻排完这一本的批注与短句（段落号按总段数种子散开、当场落库）、按读到的进率说一句、先走、房间回话；txt / md / html / epub（自己拆 zip）解析成段落，「只有书名」的没有进度就一秒不计、一处不写 |
| `apps/web/src/lib/engine/diary.ts` · `lib/diary.ts` | 日记的**排程 / 事实收集**：我的不限条数；他自动那条每天最多一次（到点 / 我写完之后隔一会儿，**种子 = 日期**，不存任务表）；`collectFacts()` 从今天的聊天与记录里数出**真实发生过的事**（聊了几条 / 通话 / 红包 / 语音 / 礼物 / 一起听 / 一起看片读书 / 陪伴多久 / 朋友圈互动 / 来信），一条都没有就一条都不提 |
| `apps/web/src/lib/engine/world.ts` · `lib/world.ts` | 世界感知的**排程 / 换算**：他那边的钟点真换算（时差是我设的）、状态与「正在做的事」按时段分池抽（**种子 = 日期 + 采样槽**，槽长 = 当天抽出的采样间隔）、`toChat` 每天最多在聊天里说一句；**天气没有源就恒为 `null`，不编** |
| `apps/web/src/lib/engine/check.ts` · `lib/check.ts` | 查岗的**排程 / 报告**：冷却现算（从上次发起）、他 3~12 秒后回（`respondAt` 存记录，钟到点结算）、报告里「真的」那栏由 `realFacts()` 从本机记录现算、「抽的」那栏是定位与手机屏（种子 = 请求 id）；他每天最多来查你 `checkPhone.dailyLimit` 次（1~5，默认 1） |
| `apps/web/src/lib/engine/search.ts` · `lib/search.ts` | 联网搜索推送的**排程 / 选形态 / 出卡**：一个间隔里按 `search.p` 抽一次（种子 = 日期 + 间隔槽）、主题同种子抽、免打扰不说；后端代取博查（`apps/server/bocha.mjs`）+ 验图与抓封面（`apps/server/media.mjs`）；**只有 `searchWeb` 说 ok 才推卡**，搜不到就只记一条失败轨迹 |
| `apps/server/media.mjs` | **形态判定 + 素材验证**：一条结果是不是视频页（域名 / 页面自带 `og:video` —— 只有这两路硬信号）、候选图真取一遍才作数（≥20KB、短边 ≥320px、不是超宽横幅）；**只验证不生成** |
| `apps/server/bocha.mjs` | 博查 Web Search 的最小封装：请求体符合契约（`query` / `freshness` / `summary` / `count`）、响应归一化（两种外层形状都认）；读不懂就当失败（`BAD_RESPONSE`），**绝不猜一条出来** |
| `components/chat/MessageActionSheet.tsx` | 长按消息 →「看抽签」：把这条的抽签轨迹（`messages.plan`）摊开给人看 |
| `apps/web/src/lib/stats.ts` | 抽签轨迹的**消费方**：统计 / 适应度页只用真数据（`plan.cardIds` 按轮去重算「他抽过我哪些卡」、`plan.silent` 算已读不回、`latencyMs` 算平均回复间隔）——没有自己的概率项，也不落任何统计表 |

**与 `engine/reply-engine.ts` 的差异（本机没有 Key 的部分，一律「只记录、不伪造」）**：

| 项 | 本机行为 | 接通后 |
| --- | --- | --- |
| 自由造句 | `compose.ts` 模板兜底（字卡库为空时会按语气回一句，如「在呢，怎么了」） | 换 `integrations/llm` 的 `composeSentence` |
| 拼音造句 | ① 优先取字卡库里「全 ASCII 的拼音卡」② 否则用内置常用字表转写，**覆盖率 < 80% 就跳过**（不发半截乱码） | 换完整拼音库 |
| MiniMax 语音 | 命中但未配置 Key → 写进 `trace.skipped`，**不发假语音** | ✅ 已接通：设置 → 接入 填 Key（或 `.env` 的 `MINIMAX_API_KEY` / `MINIMAX_GROUP_ID`）→ `INTEGRATIONS.tts = true`；命中后把这一轮**本来就要说的某一句**留给 `runtime` 合成，挑句子会避开拼音串与超过 `voice.maxCharsPerVoice` 的长句，合成失败**退回文字**并把原因写进轨迹 |
| 联网搜索推送 | ✅ 已接通：**独立的推送排程**（不在「回你」这条链上）—— 在一个间隔里按 `search.p` 抽一次签（种子 = 日期 + 间隔槽），抽中就**真去搜**；搜到才推那张 `SEARCH_PUSH` 卡（标题 / 链接 / 摘要都是搜索服务真返回的），搜不到（没配 Key / 断网 / 被限流 / 一条结果都没有）**一条消息都不发**，只在「搜索轨迹」里记一条失败 | `search_pushes`（多端由服务端定时任务发起，同一套 `search.*`） |
| 情绪 / 心意标签 | `compose.ts` 关键词打标（心动 / 心疼 / 温柔 / 认真听…） | 换 `engine/emotion.ts` 的模型打标 |
| 主动行为 | ✅ 本机定时器（`lib/engine/proactive.ts` + `runtime.ts`）：安静够了就自己发一条，气泡左上角 ❤️ | `proactive.module.ts` + BullMQ（多端用，同一套 `proactive.*` 规则） |
| 朋友圈 / 信箱 | ✅ 本机时间轴（`lib/engine/timeline.ts`）：主动发动态、点赞评论、回赞、写信回信、蓝笔批注；文案由 `content.ts` 用模板 + 他的字卡库拼 | `timeline.module.ts`（占位）+ BullMQ（多端用，同一套 `moment.*` / `mail.*` / `proactive.moment/letter` 规则） |
| 陪伴 | ✅ 本机引擎（`lib/engine/companion.ts`）：**真计时**（真实秒数，到点封顶）+ 种子抽签（到场 / 中途说话 / 先走 / 房间回话），结束时落一条 `SYSTEM` | `companion` 房间同步（WS 多端一起陪，`context=COMPANION`） |
| 观影室 | ✅ 本机引擎（`lib/engine/watch.ts` + `lib/videoEl.ts`）：进度是真的（`<video>` 在走才累加、每 10 秒落盘）+ 种子抽签（到场 / 排弹幕 / 按进度说一句 / 先走 / 房间回话）；B 站与只有片名的**一秒不计、一条不飘** | `watch_rooms` + WS（多端同一部片同步播放位置；本机版本已经能自洽运行） |
| 阅读室 | ✅ 本机引擎（`lib/engine/read.ts` + `lib/read.ts`）：读秒与段号是真的（开着 + 前台 + 45 秒内翻过页才累加、每 10 秒落盘）+ 种子抽签（到场 / 排这一本批注 / 按进率说一句 / 先走 / 房间回话）；「只有书名」的**一秒不计、一处不写** | `read_rooms` + WS（多端同一本同步段落位置；本机版本已经能自洽运行） |
| 日记 | ✅ 本机引擎（`lib/engine/diary.ts` + `lib/diary.ts`）：我的不限条数（每条按 `id` 独立改 / 删 / 公开私密）、他自动那条每天最多一次、留言里提到的每件事都是从今天的记录里**真数出来的** + 种子抽签（写不写 / 几点写 / 提不提真事 / 几句 / 会不会顺着我写），**种子 = 日期**、不存任务表 | `diary_entries`（本地按 `id` 存，同一天可多条） |
| 世界感知 | ✅ 本机引擎（`lib/engine/world.ts` + `lib/world.ts`）：时差换算与采样时刻是真的 + 种子抽签（状态 / 在做的事，**种子 = 日期 + 采样槽**）；**天气没有源就不显示** | `world_sense_logs`（`timeOffsetMin` / `status` / `doing` / `weather` 对得上；`weather` 在没接源时一直是 `null`） |
| 查岗 | ✅ 本机引擎（`lib/engine/check.ts` + `lib/check.ts`）：冷却与报告里「真的」那栏是从本机记录现算的 + 种子抽签（同意与否 / 定位与手机屏 / 「修饰过」），他回应的时刻存在 `respondAt`；**真的截图与坐标永远不给** | `check_requests`（`REQUESTED → AGREED / REFUSED`；`EXPIRED` 只在多端版出现） |

> 复盘入口：**长按任意一条消息 →「看抽签」**，能看到「已读不回 → 拍一拍 → 载体抽签 → …」每一步命中了没有、抽中哪张卡、为什么跳过语音。抽签结果也存在消息上（`messages.plan`），刷新不丢。
> 我发的那条也会挂上这轮轨迹（我这条是怎么被「处理」的），并在气泡下方显示 **`✓✓ 已读` / `已读不回`** 小角标 —— 他没有「回执」这套微信行为，这里的角标是专门加的可视化，不影响第 1 步抽签本身。
> 拍一拍库（`lib/pats.ts` + `components/chat/PatPanel.tsx`）：**我的拍一拍**在聊天「+」→ 拍一拍 / 点他的头像时手动发；**他的拍一拍**由第 2 步抽签使用（可逐条启停），整句形如「梦角」拍了拍我的**后脑勺**。

`pickup` 命中时会真的往他的字卡库塞一张 `source: PICKED` 的卡（同内容自动去重），所以在字卡库里能直接看到「拾取」Tab 长出新卡。

## 与字卡库的关系（三层概率）

引擎的 `chat.weights` 只决定**载体类型**；具体抽到哪一张卡由字卡库的 `cards.weight` 决定：

```
第 ① 层  类型占比   chat.weights{text,kaomoji,sticker,image} 归一化（emoji 归入 text 池）
第 ② 层  卡内权重   同一「占比池」内按 weight 归一化；权重全为 0 时该池不参与抽签
第 ③ 层  综合命中率 ① × ② —— 字卡库列表里每张卡显示的「命中」就是它
```

配套的卡级开关（不占 `rule_configs`，存在 `cards` 行上）：

| 字段 | 作用 |
| --- | --- |
| `enabled` | 停用后不参与抽签，`weight` 保留，随时可恢复 |
| `noFreeSentence` | 系统预设默认开启：禁止把这张卡喂给 LLM 做「自由造句」，保证预设原句原样出现 |
| `useCount` / `lastUsedAt` | 每次抽中 +1（`POST /cards/:id/use`），供统计与后续「用腻了降权」策略 |

> 所以「调占比」和「调字卡库」是两个入口、同一套概率：前者定类型，后者定卡。
> 抽签实现见 `apps/web/src/lib/cards.ts`（`cardRates`）与 `apps/web/src/lib/simulate.ts`。
